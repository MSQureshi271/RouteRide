# T1.13 and T1.14 implementation

These tasks follow ADR-011 and the Phase 1A service-area amendment. T1.14 means
pending request creation from `todo.md`; acceptance is T1.16.

## Implementation

- T1.13: authenticated, commute-specific public driver profile and mobile detail
  screen. Validate rider ownership and current requestability for a targeted
  driver. Return public vehicle and verification information, rating distribution
  and paginated anonymous verified reviews. Exclude private route geometry,
  starting location, roster, contacts and documents.
- T1.14: authenticated `POST /subscriptions` with a required `Idempotency-Key`,
  server-side ownership/coverage/availability checks, price snapshot, independent
  requested leg windows, and a 24-hour response deadline. Store PENDING only;
  no seat, run, slot, trip or billing allocation.
- Additive schema migration separates requested terms from agreed service fields.
  Pending requests leave agreed timestamps and next billing date unset.
- Public API documentation is generated from the new shared response contracts.

## Remaining lifecycle scope

The mobile request form/submission integration is T1.22. Profile navigation does
not send a request. Driver preview, acceptance, expiry and withdrawal remain their
separate Phase 1B tasks. Native-device verification remains required before task
completion is recorded.

## Migration and rollout

`20261022T1503_pending_subscription_requests` adds the snapshot/deadline fields and
indexes, permits unset legacy agreement fields, and checks snapshot/deadline
pairing plus unbilled new PENDING requests. Existing legacy records are preserved.
The full migration chain was replayed in the dedicated database. The development
database was not migrated or reseeded during this implementation.

Before running the new request endpoint against a different database, confirm its
target and apply the checked migration chain using
`pnpm --filter @routeride/api prisma:migrate`. Deploy the migration before the API.
Rebuild shared contracts before starting dependent applications. Native device
layout, font scaling, screen-reader and authenticated live-flow verification are
still required before checking these tasks off.
