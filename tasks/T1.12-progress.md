# T1.12 — Mobile search results and driver cards

Implemented on 2026-10-22 against the service-area amendment and ADR-011.

The consumer results screen uses a virtualized, paginated list in server ranking
order. Shared `DriverCard` renders vehicle information, nullable ratings as
"New driver", integer-paisa monthly prices, seats, the searched availability,
geographic distances or "No established route", and driver review status.
Its review action preserves commute context and does not submit a request.
Loading uses skeleton placeholders; empty results offer a schedule adjustment;
errors offer retry and adjustment actions. The v2 response has no exclusion-reason
field, so the screen does not invent dominant failure reasons from the old v1 API.

- `packages/ui/src/components/DriverCard.tsx`
- `packages/ui/src/index.ts`
